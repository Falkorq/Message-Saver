# Отдельный доступ к MTProto

Основной бот и Mini App доступны по обычному /grant. Мониторинг профилей через аккаунт
оператора и резервные аватарки доступны только MY_ACCOUNT_IDS / MY_CHAT_ID и пользователям
из MTPROTO_ALLOWED_USER_IDS. ID — Telegram user ID; для дополнительных пользователей
обычный доступ создаётся один раз при первом запуске этой версии; /revoke сохраняется после перезапуска. SECOND_* автоматически доступа к MTProto не получает.

Пример в .env:

```
MTPROTO_ALLOWED_USER_IDS=6640457762,6851862358,803489862
```

После изменения списка перезапустите бот. При отсутствующем или пустом значении используется группа 6640457762,6851862358,803489862. Чтобы исключить участника, задайте явный список остальных ID и отзовите его обычный доступ при необходимости.
/revoke закрывает доступ к боту и MTProto даже для ID, который остался в отдельном списке.
Удаление ID только из списка MTProto оставляет обычные функции бота.

Проверяются команды, старые/поддельные кнопки, ввод добавления профиля, вызовы сервиса,
фоновые проверки и резервные аватарки. Публичный /menu сохраняет инструменты и статистику,
но не показывает разделы профилей. /start не предлагает команды профилей обычным пользователям.
Новые уведомления профилей помечаются отдельно; перед их отправкой право проверяется вновь.
Старые уведомления text_notification не содержат признака происхождения и автоматически
не переклассифицируются; список доступа не удаляет уже сохранённую историю профилей.

Аватарки из Bot API остаются доступны обычным пользователям. В кэш добавлен источник:
bot или mtproto. Фото mtproto не выдаётся владельцу без действующего разрешения. Старые
записи без известного источника удаляются из кэша и загружаются заново; сообщения,
история профилей и агрегаты не удаляются. Ограничения очереди и MTProto-бюджет сохраняются.

Это контроль доступа к общему аккаунту, не отдельная сессия для каждого пользователя.
Разрешённые пользователи по-прежнему пользуются видимостью и общими лимитами оператора.

Полный FloodWait сохраняется в общей таблице mtproto_runtime и проверяется после ожидания общего lock, включая ручные проверки и аватарки. Ручных действий — до 10 в минуту на владельца и 30 на общую сессию; активных целей — до 100 на владельца. Бюджет резервных аватарок 30/час сохранён.
