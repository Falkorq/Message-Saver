# Обновление через Pterodactyl / NimarkoHost

## До обновления

1. Остановите бот кнопкой Stop. Убедитесь, что другой экземпляр с тем же токеном не работает.
2. Сохраните **существующий** `.env`, включая `MESSAGE_ENCRYPTION_KEY`, отдельно от базы и отдельно от публичного архива. Ключ не создавайте заново. Сохраните актуальный `erasure-guard.aes`, если он уже есть.
3. Сделайте зашифрованный снимок базы. Если установлена эта версия, выполните `python storage_admin.py backup`. Для первого перехода сначала сохраните штатную резервную копию остановленного сервера в защищённом месте; её шифрование и права должны быть подтверждены. Копия миграции не является регулярным резервированием.
4. Запишите текущие PY_FILE, DB_PATH, профильный каталог, порт и пути сертификатов. Не публикуйте содержимое .env и логи с секретами.

## Загрузить архив

1. Загрузите и распакуйте `nyan-message-hosting.zip` в каталог приложения. Он содержит код, веб-ресурсы, документацию и `.env.example`. В нём нет .env, баз, ключей, сессий, пользовательских фото и копий.
2. Сохраните прежние `.env`, базу с её WAL/SHM, профильные данные и журнал удалений на месте. Не заменяйте свой `.env` файлом `.env.example`. Не удаляйте рабочую базу.
3. Обновите зависимости из `requirements.txt` штатным механизмом Python egg панели. Для команды в терминале: `python -m pip install -r requirements.txt`. Тестировалось на Python 3.14; требования рассчитаны на современные поддерживаемые Python, но конкретный образ хостинга нужно проверить.
4. В существующем .env при необходимости добавьте реальный `SUPPORT_CONTACT` и `BOT_USERNAME` существующего общего бота. Сохраните WEBAPP_URL, порт, сертификаты и настройки Cloudflare. Рекомендуемое значение закрытой группы: `MTPROTO_ALLOWED_USER_IDS=6640457762,6851862358,803489862`. Обычный /grant не расширяет эту группу.
5. Если предыдущая база ещё содержит открытые тексты, при остановленном боте выберите `PY_FILE=prepare_encrypted_storage.py` и запустите один раз. Эта версия требует уже существующий ключ из .env и не генерирует его. При ошибке ключа остановитесь и восстановите правильный .env; не запускайте генератор ключей. Затем верните `PY_FILE=app.py`.
6. Запустите `app.py`. Добавление таблиц/столбцов автоматическое и аддитивное; прежние сообщения и агрегаты не удаляются миграцией. Backfill идёт ограниченными пачками. Дождитесь его завершения перед оценкой итогов.

Первый запуск однократно создаст обычный доступ трём ID закрытой группы. Это не открытая регистрация. Если кто-либо из них не должен пользоваться ботом, `/revoke ID`; отзыв сохраняется при последующих перезапусках.

## Проверить после запуска

- `/menu`, `/connect`, `/status`, `/chatstats`, `/notifications`, `/data`, `/help` работают без MTProto. В общем меню нет /watch и /watchlist.
- `/help`, `/privacy`, `/terms` на поддомене статистики открываются в обычном браузере без входа. Убедитесь, что загружены `public_pages.py` и `business_tools/web/public.css`. Кнопки бота используют текущий `WEBAPP_URL`; `PUBLIC_SITE_URL` можно оставить пустым.
- После приглашения тестовый пользователь видит инструкцию, подключает свой аккаунт и получает правку/удаление тестового сообщения. Проверяйте на специально созданной тестовой переписке с согласия участников.
- В Mini App правильные аккаунт, начало наблюдения, пустые состояния, собственная статистика и время обновления; чужие account/chat недоступны.
- `/healthz` становится 200 после живого polling и первого прохода очистки. 503 при задержке требует проверки очередей; автоматический бесконечный restart не нужен.
- В панели нет открытых текстов/секретов в ошибках. Закрытая сессия при ошибке не мешает polling и Mini App.
- Новое автоудаление закрыто, старые правила приостановлены. Их можно удалить через /mutelist.

Не меняйте Cloudflare и не удаляйте webhook автоматически: эта версия использует polling, как и прежняя. Если раньше был вручную включён webhook, сначала выясните фактическую схему запуска. Одновременные webhook и getUpdates не работают.

## Регулярные резервные копии

Ежедневно запускайте `python storage_admin.py backup` штатным расписанием панели или проверенной задачей оператора. Команда делает согласованный SQLite snapshot, включая WAL, шифрует весь файл существующим ключом, проверяет целостность и удаляет собственные regular-копии старше 7 дней. Запуск возможен рядом с работающим ботом; для крупной базы лучше период низкой нагрузки. По возможности используйте режим обслуживания при первых проверках нагрузки.

Копируйте полученный `.sqlite3.aes` на отдельное защищённое хранилище. Сохраняйте самый свежий `erasure-guard.aes` **отдельно от старых снимков** после каждого удаления. Отдельно храните резерв существующего .env/ключа, доступный только оператору. Код не может настроить off-host хранение или расписание панели без доступа к хостингу. Проверяйте эти задачи и сроки реально, а не только наличием каталога backups.

Миграционные копии удалите после успешной приёмки и проверенного восстановления. Старые внешние копии с удалёнными данными обрабатывайте согласно политике хранения.

## Восстановление

Сначала остановите бот. Работайте в отдельном каталоге, с копией существующего .env и самой свежей версией журнала удалений. Для копии этой версии:

```text
python storage_admin.py restore --source backups/ИМЯ.sqlite3.aes --target restored.sqlite3 --ledger erasure-guard.aes
```

Целевой файл должен отсутствовать: существующая база не перезаписывается. Команда проверяет ключ/целостность, применяет журнал удалений и помещает восстановление в карантин: удаляет старые приглашения и очереди, отключает сбор/соединения и фоновые профили. Перед использованием в .env укажите восстановленный DB_PATH. Доступы выдавайте заново; владельцу нужно явно возобновить сбор через /data и переподключить аккаунты. Проверьте собственную статистику и /healthz.

Команда также подготавливает прежнюю схему без account_state, восстанавливает принадлежность из конфигурации/соединений/статистики и применяет актуальные удаления перед карантином. Старые копии всё равно проверяйте отдельно без polling. Наличие AES-копии не доказывает успешное восстановление сервиса.

После удаления данных откат к старой базе без свежего erasure-guard.aes запрещён процедурой: так можно вернуть удалённую историю. При отсутствии журнала оставайтесь в режиме обслуживания и разберите запросы удаления до запуска.

## Что ещё требуется от оператора

До приглашения незнакомых людей подтвердите шифрование всего хранилища, WAL/временных файлов и резервных копий, отдельное хранение ключа, права доступа и изоляцию контейнера. Укажите реальный контакт поддержки и URL политики `https://stats.nyaaa.moe/privacy` в BotFather. Проверьте расписание/off-host копии и восстановление на отдельной базе. Пройдите подключение в актуальных Telegram iOS/Android, включая Back, клавиатуру, safe areas и CSV. Локальный Chrome не заменяет эту проверку.
